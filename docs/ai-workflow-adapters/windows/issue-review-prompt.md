# GitHub Issue 定期レビュー

作業先の AGENTS.md、docs/agent-workflow.md、docs/issue-workflow.md、docs/task-cleanup-check.md を読み、その優先順位に従ってください。ランナーが伝えるローカル基準ブランチと SHA を記録し、リモート最新との関係も確認します。新規着手は1回につき最大1件とします。

Issue の本文を調査・詳細化し、完了条件・対象・検証が判断できない場合は着手しません。refining、ready、in-progress、awaiting-review、blocked の状態ラベルと記録は実際のリポジトリ設定に従い、他の種類のラベルを保護します。着手・再開の前後に担当・PR・既存 run・ラベルとコメントを照合し、記録失敗や競合時は保留します。ローカルロックやラベル・コメントは分散ロックではありません。

計画・成果物は作者以外が対象版の SHA256 を照合してレビューし、指摘に対応した新版を再確認します。承認後に基準から Issue 専用 branch と worktree を作り、元 checkout の変更を保護します。再開時は旧担当の停止と成果物を確認し、必要な基準の取り込み後に検証・独立レビューを再実施します。情報が不足すれば保留し、旧承認を新たな版に流用しません。

GitHub の親子関係を確認し、サブ Issue は親統合 branch に PR を作成してマージと close を確認します。親・単独 Issue は指定された対象 branch の PR を追跡します。承認やマージを偽装せず、Issue を完了する PR のマージが確認できた場合のみ close を確認します。重複投稿を防ぐため、作成応答が不明なら識別キーで照合するまで再試行しません。

進行レビューの提案は識別キーを用いて open/closed の既存 Issue と照合し、採否にかかわらず登録を追跡します。対象リポジトリの外部投稿権限がない場合は未登録を報告します。設定ファイルは外部操作の許可になりません。Issue 更新、PR 作成、マージや削除等はそれぞれ適用指示と依頼の権限を確認します。

Windows 資格情報ストアを使う場合、適用設定に指定された認証方法とアカウントを使用し、非対話で取得した秘密をログへ出さず、一時環境変数は finally で復元します。実行中止・失敗・承認待ちは未完了として記録してください。worktree-cleanup.md を runner が指定したディレクトリに記録し、所有者・状態不明なものは保留します。
